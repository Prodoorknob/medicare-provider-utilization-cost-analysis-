Why per-state, not a monolithic gold file

The original V1 gold was a single gold.parquet. With 30% sampling on a 24 GB WSL2 instance this was workable. When Phase 2 went to full national scale, three things forced the per-state split:

PressureSymptomPer-state fix
RAMLoading the monolithic gold OOMed during V1 Phase 2 retrainingPer-state files let regional batch trainers stream by Census region
Regional batchingXGBoost --mode batch wants to incrementally train by region via xgb_model; needs predictable file boundariesEach region is the union of N state parquets, glob then concat
Iteration speedEditing the silver step required reprocessing everything to testTest on one state (CA) in seconds, then run the whole 63 in batch

Census region batch lists live in modeling/train_lgbm_local.py:71-80 and elsewhere — identical mapping copy-pasted across trainers (a code-smell that did not bite).

Bronze: the layer I ended up skipping

The bronze script (notebooks/01_bronze_ingest_local.py) tries to load every partitioned file into a single DataFrame and write a consolidated bronze.parquet. With ~10M rows times 11 years times wide schema, the in-memory representation exceeded 32 GB.

The accepted workaround is that silver reads partitioned_data/ directly. Bronze still runs on small samples for development. On Databricks, bronze runs to completion because Spark spills to disk; the local script does not. This is documented in PROGRESS.md Phase 2 notes.

Silver: typing, IQR cleaning, per-state writes

notebooks/02_silver_clean_local.py runs in two passes. Pass 1 loads only the target column from every partition file and computes a global Q1, Q3, IQR. Pass 2 reads each state's partitions, casts numerics, drops nulls on required columns, and applies the global 3x IQR bound on Avg_Mdcr_Alowd_Amt.

StepCodeDecision
Numeric coercion02_silver_clean_local.py NUMERIC_COLS listReads dtype=str at bronze; explicit numeric cast at silver to control NaN behavior
Required column dropREQUIRED_COLS = NPI, HCPCS_Cd, targetRows missing any of these get dropped; logged per state
Outlier removal3x IQR on target, globalKnown limitation: global IQR penalizes legitimately expensive surgical codes; should be per-bucket
Per-state outputsilver/{STATE}.parquetNPI is preserved here; gets dropped at gold

Gold: the 13-feature model input

notebooks/03_gold_features_local.py turns each silver parquet into a model-ready feature matrix. The HCPCS bucketing logic is at 03_gold_features_local.py:100-128, identical to the API's reconstruction in api/services/prediction.py:32-61 — the buckets must agree at training and serving time.

Feature engineering done at gold

hcpcs_bucket (0-5)HCPCS code numeric range or alpha prefixSix clinical categories: Anesthesia, Surgery, Radiology, Lab, Medicine/E&M, HCPCS Level II. Coarser than raw code (~6K unique), gives tree models a cheap split.
place_of_srvc_flagAlready present in raw, just extractedBinary facility (1) vs office (0)

specialty_bucket, pos_bucketCross of categorical featuresExplicit interaction term so shallow trees can split on it without combinatorial depth

Final gold schema (12 columns) lives in PROGRESS.md Phase 2 milestone 2.7. The encoder mappings persist to gold/label_encoders.json, used by every downstream trainer and the production API.

The two gold variants

Be careful: there are two gold directories on Drive. Use the year-aware one for any temporal model.

DirectoryHas year column?Used by
gold/No (year was stripped at an aggregation step)V1 tabular trainers, Stage 1 LightGBM V2 (year not used as feature anyway)

LSTM sequence layer

notebooks/05_lstm_sequences_local.py aggregates gold rows by (provider_type, hcpcs_bucket, state) and emits year-ordered target vectors. Output is lstm/sequences.parquet with 23,672 groups. 10,540 of those have all 11 years; 2,771 have under 3 years and get filtered before training.

What I would do differently

  • 1Stream-write bronze with pyarrow.ParquetWriter instead of holding all files in memory. Or accept bronze is a Spark-only layer and document that explicitly.
  • 2Per-bucket IQR at silver, not global. Or Winsorize at P1/P99 to preserve row count.
  • 3Add Pandera schema validation at each medallion boundary. The gold/ vs gold_year/ mistake would have surfaced as a schema assertion failure rather than a downstream Arrow error.
  • 4Preserve NPI through gold. Killed the anomaly agent and any NPPES/AHRF integration path.
  • 5Unify the local/Databricks scripts into a single Python module with a backend toggle. Right now they drift — updates to one occasionally do not land in the other.

30-second pitch

The pipeline is medallion in shape but pragmatic in execution. Bronze is a Spark layer on Databricks; locally I skip it and silver reads the partitioned CSVs directly because pandas OOMs trying to consolidate 6,313 files. Silver runs a two-pass IQR: load only the target column to compute global bounds, then per-state cleaning and typing in Pass 2. Gold is the model-ready feature layer with HCPCS bucketing into six clinical categories, log-transformed volume features, label-encoded categoricals with a persisted JSON for cross-script consistency, and an NPI-plus-year join with the Provider Summary risk score. Output is 63 per-state parquets, about 1.9 GB, that every trainer and the production API reads from.
