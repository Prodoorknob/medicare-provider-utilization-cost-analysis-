What is good

DecisionWhy I would keep it
Medallion shape (Bronze/Silver/Gold)Clear separation of raw, cleaned, and feature-engineered layers. Every downstream issue was diagnosable by pointing at a specific layer. The bronze-skip workaround did not require restructuring, just documentation.
Per-state parquet sharding at goldLet me train regionally under a 24 GB RAM budget and still iterate in seconds by testing on one state. The V2 Colab notebooks also benefit because the glob-and-concat loader is trivial.
Dual-track Stage 2 (synthetic + real PUF)A drop-in path to real MCBS LDS without rewriting anything. 08_mcbs_crosswalk_local.py --mode puf|synthetic is one of the cleanest abstractions in the repo.
No-charge ablation framingMade the production model defensible. The gap is 0.015 R² not 0.30, so the model genuinely predicts via procedure identity rather than leaning on a near-leaky charge. This is the single most defensible modeling decision in the project.
Stacker GroupKFold CVThe 5-fold split on (ptype, bucket, state) hash prevents group-level leakage that would inflate the stacker metric. Without it the stacker R² would look better and be wrong.
Unified MLflow experimentEvery run from local RF V1 to Colab V2_13 TFT logs to the same /Users/rvedire@iu.edu/medicare_models. The compare_models script pulls cross-session metrics without manual bookkeeping.
API auto-detect of model featuresbooster.feature_name() inspection lets the API serve the with-charge or no-charge LightGBM as a zero-code config swap. This made the no-charge production deployment a single file replacement.

Ideal four-week rebuild

If I started from scratch tomorrow knowing everything I know now, with one FTE, this is the plan. The objective is the same pipeline but with the honesty debts paid off up front.

Week 1 — Data ingest and bronze/silver

DayTask
Day 1-2Pull CMS Physician + Provider Summary as before. Add Medicare Physician Fee Schedule (MPFS) RVU files and GPCI tables from the start — they are the correct pricing inputs.
Day 3Partition and write Parquet. Inject year at ingest time, not via filename regex.
Day 4Silver with Pandera schema validation at the boundary. Per-bucket IQR, not global. Preserve NPI.
Day 5Specialty name canonicalization before label encoding. Audit all 131 specialty strings for Levenshtein-close duplicates.

Week 2 — Gold features and Stage 1

DayTask
Day 6Gold feature engineering with MPFS join: work_rvu, pe_rvu, mp_rvu, gpci_*. Target becomes deviation_from_fee_schedule.
Day 7LightGBM V2 no-charge on full data, temporal split 2013-2021 train / 2022-2023 test. Add year as a feature.
Day 85-fold stratified CV with std reporting. Drop the ensemble experiment — we already know it buys nothing.
Day 9Fit LightGBM + log feature importances, confusion-matrix-style error analysis by specialty and bucket.
Day 10Export booster and encoders. Write integration test: feed known inputs, assert known outputs, compare training-time features to serving-time features row-by-row.

Week 3 — Stage 2 + Forecast

DayTask
Day 11MCBS PUF pipeline. Track A only initially (real national aggregate) — skip synthetic Track B until someone funds MCBS LDS.
Day 12Fit modulation coefficients from real PUF Cost Supplement rather than hardcoding. Generate synthetic only if needed for regional granularity.
Day 13Stage 2 CatBoost monotonic P10/P50/P90 + CQR calibration. If coefficients were learned from real data, monotonicity constraints should fit now.
Day 14Forecast sequence prep with autoregressive eval from the start — no teacher-forcing eval. Temporal split train ≤ 2021, val 2022-2023.
Day 15LightGBM stacker over LSTM + Chronos-Bolt-cpi-cf-deflated. Train quantile stackers at alpha {0.1, 0.5, 0.9} for real uncertainty bands.

Week 4 — Serving and frontend

DayTask
Day 16FastAPI scaffold with health, predict (Stage 1, Stage 2, full), forecast, reference endpoints. Shared constants module for Census regions, STATE_TO_REGION, HCPCS bucketing.
Day 17Integration tests: hit local API with 50 golden requests, assert within tolerance.
Day 18Supabase schema for precomputed tiers. Write upload scripts with idempotent upsert.
Day 19Next.js frontend with SWR for reference endpoints, raw fetch for predictions. One page per product surface. Geographic choropleth on the state summary.
Day 20Railway + Vercel deploys. Structured logging and at least one Grafana dashboard.

The rebuild is roughly the same shape because the architectural decisions were mostly right. The wins are paying off measurement debt (teacher-forcing, single-split metrics), data debt (specialty canonicalization, per-bucket IQR, NPI preservation, MPFS integration), and serving debt (tests, logging, shared constants). The lost weeks are the V2 ensemble (13.3 hours for +0.0004 R²), V2_05 zero-inflated, and the three failed Chronos derivation variants.

Per-role things to volunteer before being asked

Data Engineer interview

  • The year column silent-failure on filename-regex reconstruction
  • The bronze-OOM workaround and the trade of not consolidating locally
  • Global IQR is wrong; per-bucket is right; documented but not fixed
  • No schema validation at medallion boundaries — the gold vs gold_year mistake would have surfaced as a Pandera assertion
  • NPI preservation would unlock NPPES, AHRF, and the anomaly agent spec; it got dropped by accident at gold
  • Local/Databricks script drift — I would merge via a backend flag, not keep two copies

ML Engineer interview

  • The LSTM teacher-forcing bug that invalidated V2_09 through V2_11 interpretations
  • The no-charge ablation as the defensibility lever for Stage 1 production
  • The ensemble negative result: Ridge over XGB+CatBoost+LGB picked LGB with weight 1.12; +0.0004 R² for 13.3 hrs
  • Multivariate TFT tied univariate LSTM because covariates at annual resolution move in lockstep with the target
  • Stage 2 V2 monotonic lost because synthetic data does not obey the priors; real MCBS LDS would likely revive it
  • The OOP CQR calibration miss: V2_04 logged q_hat=$3.6884 to MLflow at training time but never exported it as an inference artifact. Production served raw quantiles for two weeks (raw P90 marginal 67.5% vs nominal 90%) until commit c389a02 added the asymmetric sidecar. The lesson: training-time validation is not a serving-time guarantee — calibration constants must be artifacts that the loader actually reads.
  • GroupKFold on (ptype, bucket, state) hash for the stacker CV to prevent leakage
  • No CV variance on single-model results — I quote R² to 4 decimals and defend to 2

Data Scientist interview

  • Why Stage 1 R² and Forecast R² are not comparable (row-level vs group-year aggregate)
  • The leakage cleanup that took the V0 toy result from R² 0.9996 to where real modeling could start
  • Submitted charge dominance at 62% in V1 that looked like leakage; ablation showed it was not (cost of removal was 0.015 R², not 0.30)
  • Synthetic OOP uses hardcoded modulation factors, not learned coefficients — product-visible limitation
  • Signal ceiling argument: three architectures cluster at 0.857-0.869, only ensemble diversity breaks 0.88
  • Quarterly data is the only lever left to push forecast R² meaningfully higher

Top-5 "what I would do differently" across the project

  • 1Write the LSTM autoregressive eval from day one, not teacher-forced. One hour to implement, saves eight weeks of confused comparisons.
  • 2Canonicalize CMS specialty names at silver before encoding. Cheap. Would have prevented the Cardiology / Colorectal / Oral Surgery split.
  • 3Integrate MPFS RVUs from the start. Target "deviation from fee schedule" rather than "allowed amount" makes the model publishable.
  • 4Temporal split for tree models too. Random 80/20 on year-dependent data is sloppy.
  • 5Write integration tests before the first production deploy, not after. Feature-reconstruction parity bugs are invisible until they are not.

30-second pitch (critical version)

The project is shipped and deployed with three production models serving real-time predictions. What I would do differently is pay off the honesty debts up front. The LSTM eval was teacher-forced until I discovered it in Phase 8 and it invalidated my Chronos comparisons; Stage 2 is trained on synthetic data with hardcoded modulation factors rather than coefficients learned from the real PUF; CMS specialty names rename across years and split Cardiology into two encoded indices; I did not integrate the Medicare Physician Fee Schedule which is the actual pricing mechanism. The architectural calls were mostly right and I would keep the medallion shape, the per-state sharding, the dual-track Stage 2, and the LightGBM stacker. The four-week rebuild is the same pipeline minus the measurement and data debts.
